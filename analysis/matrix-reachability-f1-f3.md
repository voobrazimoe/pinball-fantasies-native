Two independent Gameshow defects were found:

1. **The reported live crash** — the native bonus-multiplier label is built with the
   12-digit BCD `Decimal.String()` formatter, producing `_BONUSX000000000002TS`
   instead of the source label `_BONUSX2TS`.
2. **A second, previously unknown crash** — `BEATEN_BH_TS` (the shared
   `FANTASIE.ASM _beaten_matrix` target) is defined at `SHOW.ASM:1031`, just
   outside the table-3 extractor region `[1032:1766]`, so it was never registered
   while `internal/gameshow/matrix.go` jumps to it on every high-score-beating
   ball loss.

Party Land and Speed Devils have no missing matrix targets: every source-reachable
program name (literal, effect-table-selected, pointer-table-selected, dynamically
formatted, and branch-only) resolves in their runtime maps.

## 2. Method

The audit is source-authoritative; native behaviour is only a cross-check.

1. **Whole-file ASM parse** (`tools/matrix_reachability.py`).
   All `NAME LABEL WORD` / `NAME DW _OP,...` command words are parsed from the
   whole file, not only from the extractor's hardcoded region, so a program that
   sits outside the region is still discovered. `COMMENT\` blocks and
   `IF DEMOVER` bodies are blanked exactly as the extractors do.
2. **Source roots from the ASM effect tables.** `EFFECT_STRUC` blocks
   (`NAME DW jingle` / two 12-digit BCD rows / `DW matrix`) are parsed directly from
   the ASM; the matrix column plus native string literals (`beginMatrix`/
   `matrixJump`) form the entry-root set. This does not depend on the native effect
   maps for what is reachable.
3. **Source graph fixpoint.** From the roots, the graph is followed through
   `_JMP`, `_JBCDZ`, `_JBONUSX1`, the shared `_BEATEN_MATRIX` → `Beaten_bh_TS`
   hop, and real label fallthrough (labels are entry markers into one shared
   stream). Traversal stops only where the native runtime stops dispatching
   (`0`, `_JMP`, `_CHECK_XXBALLS`, `_CHANGE_PLAYER`, `_2_DEMO_MODE`, `_TURNONTURBO`).
4. **Dynamic family resolution.** Selector domains are taken from the ASM
   (`BONUSTABLE`, the ordered `LIGHTSTATUS` checks, the multiplier-lamp range,
   the speed clamp), and formatted names are reproduced using the *actual*
   native formatter (`internal/tablelogic/decimal.go` `Decimal.String()` = `%012d`),
   not the intended decimal text. This is what exposes bug (1).
5. **Native dispatch emulation.** The registered command stream is walked exactly
   as the Go `matrixDispatch` walks it (including its literal hops), and every
   branch target, `_ANIMATION`, `_SCROLL` and `_JINGLE` it can name is checked for
   resolution.
6. **Diff and fail.** `source-reachable − registered` and the dynamic/emulated
   target sets must be empty or the checker exits non-zero and lists the exact
   identities.

Run:

```sh
python3 tools/matrix_reachability.py                 # audits this checkout
python3 tools/matrix_reachability.py --root /home/mess/work/PINBALLF   # read-only audit of another tree
```

`--root` only selects the tree to *read*; the generated Go data files are always
written into the checkout that contains the tool, never into the audited tree.

## 4. Root cause of the reported `_BONUSX000000000002TS` crash

**Original ASM construct** (`SHOW.ASM`):

```
136  bonusmultiplier db ?
137  BONUSTABLE DB 2,3,4,6,8,10
138  BONUS_ANIMS DW _bonusx2TS,_bonusx3TS,_bonusx4TS,_bonusx6TS,_bonusx8TS,_bonusx10TS
...
3497 cmp  bonusmultiplier,6
3498 je   DUMRET
3499 inc  bonusmultiplier
3500 MOV  BL,BONUSMULTIPLIER
3501 NIL  BH
3502 dec  bl
3503 SHL  BX,1
3507 mov  bx,BONUS_ANIMS[BX]
3508 call do_matrix
```

`BONUS_ANIMS` is registered correctly by the extractor: table 3's
`presentation.Content.Labels` contains `_BONUSX2TS`, `_BONUSX3TS`,
`_BONUSX4TS`, `_BONUSX6TS`, `_BONUSX8TS`, `_BONUSX10TS` (from `SHOW.ASM:1159-1189`).

**Native code that generated the bad name** (`internal/gameshow/rules.go:290`):

```go
g.beginMatrix("_BONUSX" + number(uint64(g.Multiplier)).String() + "TS")
```

`number` is `tablelogic.Number`, and `Decimal.String()` is
`fmt.Sprintf("%012d", d.Uint64())` (`internal/tablelogic/decimal.go:22`).
The string therefore became `_BONUSX000000000002TS`, which is not a source label.

**Extractor/normalisation step that failed**: none in the extractor — the labels
exist; the defect is purely the native name construction. `beginMatrix` upper-cases
its argument, so `_BONUSX2TS` (from `_bonusx2TS`) would have resolved.

**Complete family**: `_BONUSX{2,3,4,6,8,10}TS`; the broken construction produced
`_BONUSX00000000000{2,3,4,6,8,10}TS`. All six members were missing.

**Fix**: build the plain decimal label, e.g.

```go
func bonusMultiplierLabel(multiplier uint8) string {
    return "_BONUSX" + strconv.Itoa(int(multiplier)) + "TS"
}
```

## 5. Second defect: `BEATEN_BH_TS` is outside the F3 extractor region

`FANTASIE.ASM:4032-4058` implements the shared `_beaten_matrix` command:

```
4034 cmp already_beaten,true
...
4057 mov bx,offset beaten_bh_ts
4058 JMP [BX]
```

Each table defines its own `Beaten_bh_TS`:

| Table | Source line | Extractor region | Registered |
|---|---|---|---|
| F1 | `PLAND.ASM:1286` | `[1280:2007]` | yes |
| F2 | `SDEV.ASM:1191` | `[1187:1935]` | yes |
| F3 | `SHOW.ASM:1031` | `[1032:1766]` | **no** |

`tools/reference_pf8.py:53` slices `s[1032:1766]` for table 3 (0-based), which
starts *after* the label line 1031 (0-based 1030). The following `BeatenTS`
(line 1044) is inside the region, which is why `BEATENTS` was registered but
`BEATEN_BH_TS` was not.

`internal/gameshow/matrix.go:131-135` ports the shared command faithfully:

```go
case "_BEATEN_MATRIX":
    if g.beatHighScore() {
        g.matrixJump("BEATEN_BH_TS")
    }
    continue
```

`matrixJump` looks the label up in `Display.Content.Labels` and panics when it is
missing (`missing SHOW branch BEATEN_BH_TS`). This is reachable in real gameplay:
the ball-loss bonus sequence contains `_BEATEN_MATRIX`, so a player who overtakes
the high score and then loses a ball crashes here — independent of the
`_BONUSX` bug.

**Fix**: change the table-3 region origin from `1032` to `1030` in
`tools/reference_pf8.py` and regenerate `internal/presentation/content.go` and
`analysis/pf8-content.json` (`python3 tools/reference_pf8.py`).

## 7. Runtime behaviour on an impossible missing lookup

Recommendation: **keep the panic/assert.**

* All valid source-reachable targets now exist, and the completeness checks below
  fail loudly if a future extraction drops one.
* An impossible target is an invariant violation (extractor regression or a new
  dynamic name), not a gameplay event. The original `do_matrix`/`[BX]` jump had no
  fallback either.
* A silent substitute (blank matrix, clear HUD, invented program) would hide
  exactly the class of bug this audit exists to catch and would diverge from
  original semantics.
* If desired, the panic message can be enriched (table name + nearest registered
  labels) — a diagnostics change only, not a behavioural one.

## 11. Limitations

* The audit models explicit `DW` control-flow words, effect/pointer tables and the
  three shared opcode-internal jumps (`_BEATEN_MATRIX`, `_KOLLA_XXBALL`,
  `_CHECK_XXBALLS`). Frontend-owned attract/high-score/UI matrix programs are
  deliberately excluded from gameplay roots (the native frontend owns them); the
  itemised `extra_native` lists in `analysis/matrix-reachability.json` make that
  explicit rather than silent.
* The PC/DOS ASM is the authority used here; the Amiga CD32 sources were not part
  of this audit.
* The snapshot boundary above means the recommended diff must be reapplied to a
  later tree that may also contain PF10 extraction changes, especially to
  `tools/reference_pf8.py` (which the PF10 work also edits).
