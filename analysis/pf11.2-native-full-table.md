# PF11.2 — native full-table presentation and desktop fullscreen

Implemented before PF12. OFF and Alt+Enter are native presentation features, not recovered DOS video modes. No Win32 work was started.

1. **Final Options layout.** Six selectable rows: BALLS (3/5), ANGLE (HIGH/LOW), SCROLLING (HARD/MEDIUM/SOFT/OFF), MUSIC (ON/OFF), RESOLUTION (NORMAL/HIGH), SAVE AND EXIT. COLOR MODE is absent. The linked INTRO font, heading, palette, arrow, keyboard controls, 18-pixel row spacing, separator before SAVE AND EXIT, sidebar, fades and music continuity remain. No fullscreen row or mouse controls were added. See `internal/frontend/options.go` and the Options PNG checkpoints.

2. **DOS reference retained.** PF11 source fixtures and historical reports remain intact. `DecodeLegacy`/`LegacyRecord` retain the original six-byte layout: offset 0 BALLS, 1 ANGLE, 2 SCROLLING, 3 MUSIC, 4 RESOLUTION, 5 MODE. BALLS 0/1 means 3/5; ANGLE 0/1 HIGH/LOW; SCROLLING 0/1/2 HARD/MEDIUM/SOFT; MUSIC 0/1 ON/OFF; RESOLUTION 0/1 NORMAL/HIGH; MODE 0/1 COLOR/MONO. DOS had no OFF scrolling value.

3. **Native wire format.** Deterministic 11-byte binary v1: bytes 0–3 ASCII `PFNC`, byte 4 version `1`, byte 5 payload length `5`, followed by BALLS, ANGLE, ScrollMode, MUSIC and RESOLUTION at bytes 6–10. Native ScrollMode values are 0 HARD, 1 MEDIUM, 2 SOFT, 3 OFF. Other fields remain 0/1. Magic, version, payload length, exact record length and field bounds are validated. Future versions can define new payloads without ambiguity with DOS.

4. **Migration policy.** Missing user config imports installation config if available, otherwise defaults to 3 balls/HIGH/MEDIUM/music ON/NORMAL. Valid DOS or PF11 six-byte records import using DOS meanings. Valid native v1 records round-trip. Malformed/truncated records and unsupported versions produce errors from `Decode`; `Store.Load` safely uses defaults. A malformed primary record does not fall back to the installation seed. Loading never rewrites files. The next normal native save writes v1 only to the user config directory. Save keeps PF11's temporary file, file sync, close and atomic rename behavior. Invalid saves preserve the existing file; temporary files are cleaned up. Saving still occurs on table loading and program exit, following PF11's existing frontend lifecycle.

5. **Legacy MONO handling.** Both DOS MODE values map to native COLOR; byte 5 is never repurposed as OFF. Historical mode is retained in `LegacyRecord`, palette reference helpers and `physics.Game.ReferenceMode`, outside native Config. No hidden user shortcut was added.

6. **Typed settings.** `settings.ScrollMode` defines ScrollHard, ScrollMedium, ScrollSoft and ScrollOff. Native Config exposes Balls, Angle, ScrollMode, Music and Resolution. There is no native Mode field or scattered ScrollOff boolean.

7. **Original scrolling preserved.** HARD/MEDIUM/SOFT factors remain 20/11/9. Original signed smoothing, clamps, viewport targets, SCREENFORCE and SCREENFORCE2 remain in the existing camera implementation. Source scrolling fixtures are unchanged. OFF uses SOFT arithmetic internally, with the selected resolution's source viewport dimensions.

8. **Full-table compositor.** `physics.FramePalette` continues to animate source flipper deltas, use live indexed table patches and the source spring graphics, apply the lamp palette and draw the ball through the original foreground masks. OFF calls that same compositor with table origin zero and height 576. Camera/tilt presentation offsets do not displace its table or ball. No separate simplified renderer was introduced. `presentation.ComposeFullTable` performs only final placement. Existing source ordering and table-local patch ownership remain intact.

9. **Matrix placement.** `Display.DrawAt` changes the destination Y only; `Draw` retains the historical bottom-placement API. The same dots, fonts, bitmap operations, command streams, flash behavior and palette chronology render at Y=0 for OFF. Attract, pause, quit questions, game-end and initials overlays use the same placement policy. Scrolling modes keep the bottom matrix.

10. **Exact geometry.** OFF is 320×609: matrix rows 0–32; playfield rows 33–608. Table row y maps to output row 33+y. The playfield remains 320×576 and the matrix 320×33. A synthetic row-identity regression and exhaustive per-row comparisons against the existing viewport renderer prove no missing, duplicated, cropped or resampled logical rows.

11. **Forced camera states.** RASTERPOS, SCREENPOS, SCREENFORCE, SCREENFORCE2, capture and target state continue updating. Tests check that SCREENFORCE still writes its source raster while changes to raster and screen offset cannot move OFF pixels; SCREENFORCE2 is likewise visually inert. Held-ball capture checkpoints exercise the fixed composition path. These fixtures are controlled capture/camera states, not exhaustive playthroughs of every capture sequence.

12. **Resolution interaction.** NORMAL remains 207+33=240 rows, HIGH 317+33=350. OFF supersedes either with 576+33=609 without changing persisted Resolution. Switching back to HARD/MEDIUM/SOFT restores the selected NORMAL/HIGH presentation in the next session. Options tests exercise OFF with both stored resolutions and HIGH restoration.

13. **Four-table visuals.** Party Land, Speed Devils, Gameshow and Stones all have 320×576 decoded playfields. All pass initial chute, gameplay, upper/lower ball, spring, matrix text, matrix bitmap, capture and forced-camera checkpoints. Forty deterministic RGBA hashes are pinned in `pf11.2-full-table-fixtures.json`; emitted PNGs are under `pf11.2-validation/checkpoints`. Additional dynamic-layer tests exercise upper-plane masking and raised flipper deltas on all four tables. The independent source chute-mask validation now includes OFF, retaining Stones' 28f30h mask address and settled-ball regression. Logical and actual X11 contact sheets were visually inspected.

14. **Gameplay equivalence.** Identical 1200-tick input scripts run under SOFT and OFF for each table. Recursive comparisons include private rule/state-machine variables, ball coordinates/velocity, tasks and task identities, capture state, matrix command/timer/text state, music/player state and live physics art/masks. Only Config.ScrollMode is excluded; even source camera values match. Scores: Party 2,300,000; Speed 68,950; Gameshow 44,180; Stones 87,350. No gameplay algorithms or table command streams were changed.

15. **Window/texture lifecycle.** One SDL window remains throughout selector, Options, tables and all logical heights. Only the streaming texture and renderer logical size change with the framebuffer. Physical window resize persists. SDL's aspect policy retains gameplay aspect; the frontend retains its established doubled-scanline presentation. Full uploads and renderer clears prevent stale rows. Gameplay input remains in table coordinates.

16. **MONO regression.** `MonoDAC` retains integer six-bit DAC averaging, and `MonoRGB` retains the source lamp conversion order. `TestMonoDACIntegerMean` and `TestSourceMonoLampRounding` remain active. Normal native sessions use COLOR; historical archaeology remains test/reference behavior.

17. **Persistence tests.** Tests cover missing records, installation seed preservation, both legacy MODE values, native v1 round trips, all scroll values, truncated headers/payloads, invalid fields/lengths, unsupported versions, invalid-save preservation and atomic temporary cleanup. F5 cycling, OFF retention on reload, stored NORMAL/HIGH while OFF, six-row cursor wrapping, fades and frontend audio continuity pass.

18. **Matrix reachability.** `python3 tools/matrix_reachability.py --check`: missing targets 0 for all four tables. Checker unchanged. Log: `pf11.2-validation/matrix-reachability.log`.

19. **Operands and text.** `python3 tools/matrix_operand_audit.py --check`: unresolved operands 0; source text byte mismatches 0 across 1106 texts; missing runtime text writers 0. Typed arithmetic/symbolic operands, DB/DUP expressions, SW=336, EMPTYJINGLE and PF11.1 runtime text writers remain covered. Checker unchanged. Log: `pf11.2-validation/matrix-operands.log`.

20. **Party oracle.** Explicit `settings.Legacy()` oracle remains 1200 ticks, score 2,300,000, ball 2; frame hash `aec01b3a07e1a5ba10b3c635777a6742f4abd41c09899903ea532b98d8522913`. Not rebaselined. Log: `pf11.2-validation/party-oracle.log`.

SDL window ID remains 1 and manually resized 800×600 geometry survives logical transitions. Config/score storage is isolated; aborted games create no score files. Actual window captures show the matrix at top, complete table and aspect-preserving pillarboxing. Logs and captures: `pf11.2-validation/x11-smoke.log`, `x11/` and contact sheets.

24. **Native fullscreen.** Alt+Enter toggles session-only borderless desktop fullscreen. Startup remains windowed. `WindowPresentation.ToggleFullscreen()` / `IsFullscreen()` own host state through a backend interface, preparing for a future Win32 implementation without SDL flags in frontend/gameplay/settings packages. SDL uses `SDL_WINDOW_FULLSCREEN_DESKTOP` only; no monitor mode or refresh change is requested. The same renderer, texture and SDL window stay alive. Windowed size, supported position and maximized state are retained; the SDL adapter accounts for X11 decoration offsets when restoring position. Maximized restoration leaves pre-maximize geometry ownership with SDL/the window manager.

    The platform consumes Alt+Enter before normal Enter dispatch. Left and right Alt work; repeat flags and duplicate Return downs cannot produce extra toggles. Return's make/release state is owned by the platform. Standalone Alt gameplay input remains in the original held-input path. There is no new pause rule, input reset, tracker recreation or fullscreen config field.

    `tools/smoke_pf112_fullscreen.py` validates startup windowed → resize → fullscreen → restored window, NORMAL fullscreen → HIGH fullscreen, HIGH windowed/fullscreen → OFF fullscreen, gameplay toggles and OFF fullscreen → HARD/NORMAL fullscreen → restored window. Both Alt keys and duplicate make events are exercised. Shortcut Enter does not advance frontend modes or change BALLS/config. Window ID remains 1; 800×600 at client position (1920,738) restores repeatedly from the 5120×2880 desktop. Captured content aspects match 320/240, 320/350 and 320/609. `xrandr --current` output is identical before and after, including modes and refresh rates. Audio lifecycle clear/start counters are identical across each toggle and the producer stays the same. Focus-loss behavior remains SDL's existing handling. Logs/captures: `platform-fullscreen.log`, `x11-fullscreen.log`, `x11-fullscreen/`.

25. **PulseAudio.** PulseAudio smoke not rerun: audio subsystem/lifecycle unchanged. X11 smokes use SDL dummy audio. Fullscreen smoke records existing queue-cap recovery events on a slow large software-rendered desktop; these are PF11's unchanged latency policy, not fullscreen lifecycle resets. Each fullscreen operation leaves lifecycle counters and producer identity unchanged.

26. **Original/user files.** No TABLE*.HI, installation PINBALL.CFG, SOUND.CFG, PRG, MOD or ASM files were edited. An 18-file root asset/user-data hash snapshot taken before X11 validation matches afterward; local mutable scores are now excluded from runtime asset validation. All migration/smoke writes use isolated native user storage. Logs: `original-files.json`, `original-files-check.log`.

27. **Remaining differences.** Full-table top matrix, absence of user-facing MONO, the versioned native record and borderless fullscreen are deliberate native changes. They are not attributed to DOS. No physics, rules, source text, scheduler or audio behavior was modernized. Maximized-state handling has focused backend tests; the X11 journey validates manually resized normal windows. No new full-suite failures remain. PF12 has not begun.
