# PF11.1 — Source Fidelity Hardening & PF10.2 Integration

Completed 2026-10-01 in the authoritative PF11 main tree.

PF11 Options and four-table gameplay are retained. Reachable matrix operands
are source-resolved and typed, extracted DB text bytes match assembler semantics,
all 20 inventoried rendered runtime text buffers have native writers, and the
Stones lower foreground-mask address is corrected. No new feature milestone
was started.

## Typed operands and closed source grammar

The three extractors now resolve source arithmetic and equates into `Nums`
indexed by operand. `Args` preserves exact provenance: for example Stones
`Args[0] == "2*60"`, `Nums[0] == 120`. All four dispatchers and presentation
consume typed values, including the `_MATRIXLGT` flag. Missing typed values
panic even when the raw operand happens to be a decimal literal.

The audit's Python `eval` implementation was deliberately replaced with a
recursive parser for decimal/NNh hex integers, parentheses, unary signs,
`+ - * /`, and source equates. Integer division truncates toward zero.
The extractors share this parser; Go contains no ASM expression evaluator.
Synthetic frontend replay constructs explicit typed values/provenance positions
before drawing; it does not weaken extracted-command `Num` invariants.

`tools/matrix_operand_schema.py` retains source-handler citations and arity.
`tools/matrix_operand_audit.py` independently rereads retail ASM, rederives
operands and DB bytes, and checks native generated data. It also checks all
extracted streams, including attract/static tails and flags. Missing operands,
wrong values, unknown reachable opcodes, wrong arity, missing text data and
unhandled rendered text expressions fail. `--check` does not write inventory
or bytecode files and returns nonzero for stale/incomplete data.

EMPTYJINGLE is recovered from each table's `S_Empty` record, yielding
62 / 55 / 55 / 52. The four matrix dispatchers no longer duplicate those numeric
constants. Music return behavior is numerically unchanged.

F1/F2 extraction now uses source `SW=336`, matching the shared extractor and
source VRAM stride. This is matrix memory geometry, not a change to visible
320-pixel gameplay width. Position/presentation regressions pass.

## DB and DUP semantics

DB lists split at top-level commas with quoted strings and parentheses intact.
A character arithmetic element is evaluated as one expression, then truncated
to a byte. DUP counts use the same closed parser and fail on unsupported counts;
there is no numeric-prefix fallback. Uninitialized/non-text storage using lost
include structure declarations is not treated as a rendered text expression.
The length-only Speed extractor explicitly rejects unsupported rendered scrolls.

Pinned corrected text/bytes include:

- `20 LITES EXTRA BALL` and ` 10 LITES OFF ROAD`;
- `  MONEY MANIA AT 6 ` and `XXX LITES 5 MILLIONS`;
- all four `ZEROQ` rows (`'0'+7,0`);
- SHOW `SPINscores`: all 12 bytes, including four byte-truncated 243 values;
- all four UNDANSPR lengths 256 and HIDDA lengths 1152;
- expression-valued DUP and character arithmetic parser negative controls.

The source inventory remains 1,106 buffers with zero byte mismatches.

## Runtime DATA text write-back

`Display.MutableText` copies the generated template before a write and checks
existence/length loudly. Each display already owns its text map. Package-level
extracted slices remain pristine across games, while live buffers retain their
source-style state across balls.

Speed Devils' real `loop()` award path writes MILES_TEXT from Miles at offset 5,
JUMP_AT_TEXT from NextJump, and OFFROAD_AT_TEXT from NextOffRoad. The encoded
digit is `'7'+digit`; Put_In_Text blanks the whole leading-zero run with `'*'`,
while jump/off-road loops blank only a zero hundreds digit. Rule-path, 0/7/20/123
encoding and independent-session tests pass.

Gameshow BONUS_X_TEXT is written by `_BONUS_X_CALCS` (SHOW 3978–3985), after
bonus multiplication, on every execution of that opcode. The value is the live
bonus multiplier. The source first writes encoded `10` at bytes 8/9, then
replaces it with the encoded single multiplier and a space when below 10.
The normal ball-lost program bypasses calculation at X1; the opcode itself
still has the unconditional X1 write. Tests cover both the real ball-lost
program and that opcode branch. The buffer is mutated rather than regenerated
at draw time; the next calculation overwrites both digits regardless of whether
the multiplier changed.

Gameshow SKILLTEXT is written by `anotherSkill()` (SHOW 3683–3759). The first
counter increment skips 1. Multiples of 6 take Money Mania/extra-ball branches;
quotient 1 selects SKILLSHOT_XB; quotient 0 does not write. Other non-award
hits calculate `(Skills/6+1)*6` and call Put_In_Text for exactly three digits.
Destination is byte 16 below 100 and byte 17 at/above 100; only a zero hundreds
digit becomes `'*'`. The 20-byte DB template has a trailing zero at byte 19,
which the >=100 case overwrites exactly as source. Byte 16 retains its prior
value on that case. The counter and live text survive ball reset; a new game
sees the source `MONEY MANIA AT 6` template. Tests use the actual rule transition
and include the 98->99 hit announcing 102, no-write branches, ball persistence
and new-game isolation.

Stones BONUS_X_TEXT uses the identical two-byte writer in its own
`_BONUS_X_CALCS` (STONES 5726–5733). Tests cover 1/2/3/4/6/8/10 at the opcode
layer; normal rule multipliers remain the source 1/2/4/6/8/10 family.
No bonus/scoring rule was changed.

The stronger checker exposed additional pre-existing F1/F2 gaps hidden by the
old name-only test: BONUS_X_TEXT and player digits in PARTY_ON_TEXT and
SHOOT_AGAIN_TEXT. Their exact one-byte source writes now execute in
`_BONUS_X_CALCS`, `_PARTYONN`, and `_SHOOT_AGAIN_ONN`. The native single player
is encoded as `'8'`. Existing Gameshow/Stones player/scream writers are retained.

The checker distinguishes source DATA, source runtime writes, native mutation
paths and absent writers. It requires a mutation in the function containing the
buffer label, or the explicit bonus-writer call, rather than a name mention
anywhere in a package. Absent writers are hard failures.

## Stones clipping: source evidence and exact correction

The sprite is a nominal 16x16 bitmap with 177 occupied pixels spanning 15x15.
SETBALL stores (297,530) as the top-left draw origin. PUTTHEBALL passes SC_X
and SC_Y+33 directly to PUTBALL; no hotspot subtraction is appropriate.
At that coordinate the old native mask happens not to cut the occupied ball,
but after it settles to approximately (301,537), the erroneous mask cuts its
lower-right side. Spring graphics start at (304,556), below this sprite.
The ball fits both PF11 bottom-aligned viewports and the 320x576 playfield.

Root cause: `DecodeInitialStones` read the lower foreground bitmap from
`0x28eb0`, 128 bytes too early. STONES HIDDEN1 declares UNDANSPR as 256 bytes
and HIDDA as 1152 bytes. The linked PUTTHEBALL loads ES=287Bh and BP=FB96h;
BREDDA_MASK reads HID1 from HIDDEN1:0580h and widens each 40-byte row to 42.
The correct packed mask file address is:

```
MZ header 0200h + HIDDEN1 287Bh * 10h + HID1 0580h = 28f30h
```

The smallest production fix changes only that lower-mask asset offset to
`0x28f30`. No sprite origin, start position, physics, clipping rectangle,
foreground rule, draw order, spring coordinate or viewport behavior changed.
STONES upper HID2 is correct: linked HIDDEN2=2E73h, offset0480h -> 2EDB0h.
Collision-mask addresses remain untouched.

The deterministic compositor test derives the lower-mask addresses from each
pinned linked PUTTHEBALL signature, checks every ball pixel against that mask
and palette, and verifies that masked pixels preserve foreground. Both NORMAL
and HIGH are tested. At frozen Stones SETBALL the correct source exposes 152
pixels and masks 25 at the left lane edge; at the settled chute position all
177 are visible. This preserves intentional source masking while removing the
erroneous lower-right cut. Fixtures are in `pf11.1-validation/chutes/`.

Other lower masks agree with their linked source addresses:
F1 300B0h, F2 2D4F0h, F3 1F870h. No shared compositor redesign or other table
asset correction was needed. All four start chutes pass in both modes.
