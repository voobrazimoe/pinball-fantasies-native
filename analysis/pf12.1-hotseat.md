## Selection and latch

Supported range is **1–8**, not inferred from the number of function keys alone. Table selection precedes player selection. At the selector F1–F4 load Party Land, Speed Devils, Gameshow and Stones; F5 opens options. In the loaded table's attract mode F1 starts one player, F2 two, through F8 eight. Each starts immediately: another Start key is unnecessary. Enter normally starts one player. A source quirk matters after an eight-player game: checkstartkeys tests PLAYERS>=8 **before** clearing PLAYERS_CP, so Enter is ignored in that attract state. F1–F8 still start normally; reloading the table restores the default. This is a deliberate source guard, not persisted player progress.

During the initial ball's launch area the count can still be replaced with F1–F8; Enter adds one up to eight. The keys have a 15-source-sync inhibit interval after each accepted selection. The first CLOSE1 traversal closes ADDPLAYERS for the rest of the game; later players' launch areas do not reopen selection. F1–F8 during ordinary live play do not start/restart a game. A paused game's first key resumes it without applying that key as a selection. Native focus loss requests pause. Alt+Enter remains a host fullscreen shortcut, not an Enter player-selection make.

The count is session state, never an F5 setting or CFG byte. A completed/aborted game returns to attract; selecting a fresh count creates fresh player slots. Restart returns to the normal startup/default state. F5 has no conflict: Options belongs to INTRO, five-player selection to the table program.

## Turn, round, extra-ball and game-over rules

PLAYER is one based; array addressing subtracts one. BALLS[11] is a **shared round number**, not eight separate remaining-ball counts. Initial state is P1/B1. Complete outgoing bonus processing and any hold-bonus restoration, then save the outgoing record. If an extra ball is pending, retain player and round. Otherwise advance to the next player. Only the last player's ordinary ball increments the round. Wrap to player 1 only if the new round is within the selected 3/5-ball limit. On exhaustion DOS leaves PLAYER at the last player and the round one beyond the limit, then enters out-of-balls presentation.

Thus two players have P1/B1, P2/B1, P1/B2, P2/B2; three/eight follow the same algorithm. A ball without qualifying score uses the table's source retry path rather than consuming a turn. That path is particularly visible in Party's PARTY_ON sequence. Tilt changes bonus/lamps through the existing table rules before the same turn algorithm; incoming tilt and transient ball electronics reset at NEW_BALL.

Party and Stones use the shared byte XBALLS and can stack earned extra balls. Their counts are consumed without rotating. Speed and Gameshow use the extra-ball lamp as a non-stacking latch (55/31). These do not become eight invented persistent counters: DOS never saves extra balls in PLAYER_STRUC, and rotation waits until they are consumed. Source match awards are separate from earned extra balls.

After all ordinary rounds, KNACKRUT compares each saved score's tens digit (12-byte decimal index 10) with the drawn digit. Qualifying players receive matched balls in ascending player order, each consumed once. Earned extra balls during such a turn stay with that winner. Only after all winners finish does high-score/game-over handoff complete. Match drawing shows all participants' final digits and flashes the winners. Attract/game-over replays every player's score, in player order, twice, using the source's existing matrix content.

Party's record declares happy/mega totals but neither save nor load copies them; they reset per ball. Speed declares OR/TM totals, loads them, but never saves them. Gameshow restores completed prize groups, **not** individual lit/uncollected prizes. Native TOP_THREE/ALL_SIX restoration reconstructs the won prizes. Stones preserves the kickback/ghost boundary but resets lock/capture/mode progress; one player's partially assembled multi-demon state is not another player's ball.

## High scores and storage

Scores use twelve unpacked decimal digit bytes, most significant first; native Decimal retains that representation and its existing zero/comma formatting. All four high-score scans walk PLAYER_AREA in player order, not score order. Each player is compared against the updated four-entry global list, with strict most-significant-first decimal comparison. An equal entry is not displaced, but a tied player can qualify below it by beating a lower entry. Every qualifying player enters three initials through ALFA_KEYS; Space represents `*`. Multiple players from one game can enter. The frontend queues all final decimal scores, shows the correct `HIGHSCORE PL n`, and inserts/saves after each entry; it does not submit only the last score.

The successful high-score jingle plays once, for the first qualifying player; the unsuccessful game-over jingle plays only if nobody qualifies.

No per-player files exist. Existing FileStore, userdata/fallback roots, read-only seeds and PINBALL.CFG boundary are unchanged. Native players/records never survive the session except their qualifying global high-score entries.

## Native architecture and checks

`internal/hotseat.Session[T]` owns the eight typed records, one-based identity, selection latch, round-advance decision and consumed match winners. `Game.BallNumber` remains the sole shared round byte for existing API compatibility. All counts use the same native table engine and lifecycle; there is no separate P1 engine. Each table supplies explicit SavePlayerState/LoadPlayerState hooks plus its existing reset/new-ball routine. Factory state seeds all eight slots. The frontend creates one new engine per new game, never one engine per player.

Presentation writes encoded source digits through Display.SetPlayers. Multiplayer enters FIRST_NO_OF_PLAYERSTS/NO_OF_PLAYERSTS/SHOWPLAYERSTS in the existing matrix engine. Party's narrower timing stream falls back to the already decoded presentation commands for those three panels, and the source reachability checker audits that additional command space. Linux SDL and Win32 translate all eight function-key makes to the same DOS key contract; fullscreen/pause/held-control paths are unchanged.

Regression coverage includes all four tables, player counts 1/2/3/8, 3/5 rounds, invalid counts, score independence, meaningful state isolation, shared jackpots, scrolling modes, actual bonus/drain completion, tilt cleanup, stacked/latching extra balls, multiple match winners, full three-player games through match/game-over, fresh factory slots, frontend selection/latching/pause/focus, all-player high-score order/ties and a new game after multiplayer. Private source inventory and ordinary matrix/source/numeric audits supply independent source evidence.
