# Pinball Fantasies — нативный порт на Go

[English](README.md) | **Русский**

Нативная реконструкция DOS-версии **Pinball Fantasies** для современных Windows и Linux, выполненная с опорой на оригинальные данные игры и исторические исходники.

> **Важно:** в репозитории нет коммерческих файлов Pinball Fantasies. Для запуска нужна собственная легально полученная DOS-версия игры.

## Быстрый старт

Скачайте `pinballfantasies.exe` для Windows или
`PinballFantasies-x86_64.AppImage` для Linux из
[Releases](https://github.com/voobrazimoe/pinball-fantasies-native/releases).
**Публичные бинарные файлы не содержат оригинальных игровых данных.**
Предоставьте собственные легально полученные DOS-данные Pinball Fantasies,
положив их рядом с исполняемым файлом или указав каталог через `-data-dir`.

### Обычная сборка без игровых данных

Обычная публичная/репозиторная сборка не содержит защищённые авторским правом игровые данные. Самый простой вариант — оставить оригинальные файлы DOS-версии вместе и положить рядом с ними нативный исполняемый файл.

Типичная папка выглядит так:

```text
PinballFantasies/
├── pinballfantasies.exe                 # Windows
#   или PinballFantasies-x86_64.AppImage # Linux
│
├── INTRO.PRG
├── INTRO.MOD
├── MOD2.MOD
├── TABLE1.PRG
├── TABLE1.MOD
├── TABLE2.PRG
├── TABLE2.MOD
├── TABLE3.PRG
├── TABLE3.MOD
├── TABLE4.PRG
├── TABLE4.MOD
└── PINBALL.CFG
```

Можно просто оставить в этой папке всю исходную DOS-установку целиком — удалять остальные оригинальные файлы не требуется.

#### Windows

Положите `pinballfantasies.exe` рядом с оригинальными файлами игры и запускайте его как обычную программу из Проводника.

Windows-версия — нативное x86-64 GUI-приложение на **Win32 + GDI + waveOut**. Ей не нужны SDL2.dll, MinGW или .NET.

Если оригинальные файлы лежат в другом месте, каталог можно указать явно:

```text
pinballfantasies.exe -data-dir "D:\Games\Pinball Fantasies"
```

Поддерживаются пути с пробелами и Unicode.

#### Linux

Положите `PinballFantasies-x86_64.AppImage` рядом с оригинальными файлами игры, сделайте файл исполняемым и запустите его:

```sh
chmod +x PinballFantasies-x86_64.AppImage
./PinballFantasies-x86_64.AppImage
```

Или укажите каталог с данными отдельно:

```sh
./PinballFantasies-x86_64.AppImage -data-dir "/path/to/Pinball Fantasies"
```

AppImage включает необходимые Linux-библиотеки, в том числе SDL2, но обычная публичная сборка без ассетов **не содержит** защищённые авторским правом файлы игры.

### Изменяемые данные

Файлы PRG/MOD рассматриваются как исходные данные игры и не перезаписываются. Нативная конфигурация, изменяемые таблицы рекордов и `native.log` обычно хранятся в:

```text
userdata/
```

рядом с исполняемым файлом или внешним AppImage.

Если туда нельзя писать, релизная сборка может использовать стандартный пользовательский каталог конфигурации:

- Windows: `%APPDATA%\PinballFantasies`
- Linux: системный пользовательский каталог конфигурации (`XDG_CONFIG_HOME` / `~/.config` в зависимости от окружения)

Также доступны явные параметры:

```text
-data-dir
-config-dir
-high-score-dir
```

Исходный `PINBALL.CFG` используется как read-only seed конфигурации. В обычной asset-free сборке `TABLE*.HI` — необязательные legacy/read-only seeds рекордов; без них используются встроенные заводские значения. В персональные сборки файлы рекордов не входят.

Точный перечень исходных файлов, использовавшихся при реконструкции, описан в [analysis/game-inventory.md](analysis/game-inventory.md).

## Что это вообще такое

Это не DOSBox, не интерпретатор x86 и не оболочка вокруг оригинального EXE. Игровая логика, физика столов, точечная матрица, интерфейс, воспроизведение звука и платформенные backend'ы были заново реализованы как нативный код по оригинальным данным и историческим исходникам.

Работают все четыре стола:

- **Party Land**
- **Speed Devils**
- **Billion Dollar Gameshow**
- **Stones ’N Bones**

В Windows используется нативный backend Win32/GDI/waveOut без SDL и CGO. В Linux используется SDL2. На обеих платформах работает одна и та же общая реализация игры.

## Что уже воссоздано

В нативном виде сейчас реализованы:

- оригинальная заставка и выбор стола;
- все четыре стола и их правила/машины состояний;
- целочисленная физика шара, флипперы, пружина, толчки стола и tilt;
- лампы, анимированные участки стола, foreground-маски и collision data;
- оригинальная матрица 320×33: шрифты, текст, картинки, мигание и командные потоки столов;
- очки, бонусы, extra ball, jackpot и game-over flow;
- ввод и сохранение рекордов;
- экран настроек F5;
- нативное воспроизведение tracker/module-музыки, jingles и звуковых эффектов;
- постоянное изменяемое по размеру окно и borderless desktop fullscreen;
- нативные host-backend'ы для Windows и Linux;
- детерминированные регрессионные тесты, привязанные к поведению, восстановленному из исходников.

Значительная часть работы была именно археологией: пришлось восстанавливать форматы, целочисленную арифметику, командные потоки отдельных столов, правила тайминга, изменяемый текст, скрытые операнды и детали вывода из оригинальной DOS-программы и её данных, а не собирать игру заново на современном pinball engine «по ощущениям».

## Стереозвук

В оригинальных DOS-модулях нет per-note stereo panning. Но на Amiga аппарат Paula разводит tracker-каналы характерным образом: голоса **0 и 3 влево**, **1 и 2 вправо**.

Нативный порт воспроизводит эту схему и выводит исходную четырёхканальную музыку и эффекты как **48 кГц, signed 16-bit stereo**. Сами tracker-последовательности не менялись; стереоразделение следует аппаратной схеме каналов Amiga.

Подробнее: [реконструкция аудио PF5](analysis/pf5-audio.md) и более поздние платформенные отчёты.

## Новый режим полного стола / без прокрутки

Оригинальная игра прокручивает окно просмотра по полю размером 320×576. Нативный порт сохраняет исходные режимы **HARD**, **MEDIUM** и **SOFT**, но добавляет современный вариант отображения:

**F5 → SCROLLING → OFF**

`OFF` — наше нативное расширение, в DOS такого режима не было. Он показывает весь стол сразу:

- точечная матрица: 320×33;
- полное игровое поле: 320×576;
- итоговый логический кадр: **320×609**.

Используются тот же живой renderer стола, лампы, флипперы, маски, шар и матрица; меняется только финальное представление. Физика и правила остаются теми же, что и в режимах с прокруткой. При толчке поле смещается на исходный `SCREENPOSY`, а матрица остаётся на месте. При нулевом offset сохраняется точный кадр 320×609.

Подробнее: [PF11.2 — полноразмерное отображение стола](analysis/pf11.2-native-full-table.md).
Дополнение: [PF12 — nudge и форматирование чисел](analysis/pf12-presentation-number-fix.md)
и [аудит числовых matrix sites всех четырёх столов](analysis/matrix-numeric-audit.md).

## Управление

| Клавиша | Действие |
|---|---|
| `F1` | Выбор Party Land в меню |
| `F2` | Speed Devils |
| `F3` | Billion Dollar Gameshow |
| `F4` | Stones ’N Bones |
| `F5` | Настройки в меню выбора столов |
| `Enter` | Подтвердить / начать игру |
| `Down Arrow` | Удерживать для натяжения пружины, отпустить для запуска шара |
| `Left/Right Shift`, `Ctrl`, `Alt` | Флипперы |
| `Space` | Толчок стола; повторные толчки могут вызвать tilt |
| `P` | Пауза |
| `M` | Включить/выключить игровую музыку; jingles/эффекты остаются доступны |
| `Alt+Enter` | Borderless desktop fullscreen |
| `Esc` | Назад / выход в зависимости от текущего экрана |

При вводе инициалов рекорда используются буквенные клавиши; `Space` вводит `*`, как в оригинальной таблице клавиш.

После загрузки стола **F1** сразу начинает игру на **1 игрока**, **F2** — на **2**,
**F3** — на **3**, **F4** — на **4**, **F5** — на **5**, **F6** — на **6**,
**F7** — на **7**, **F8** — на **8**. **Enter** начинает игру на одного игрока.
После игры на восемь игроков используйте F1–F8: оригинал в этот момент игнорирует Enter.
До выхода первого шара на поле F1–F8 меняют число игроков, а Enter добавляет
одного (до восьми); между изменениями действует короткая задержка оригинала.
После первого запуска число игроков фиксируется на всю игру и не сохраняется
в F5/PINBALL.CFG. Игроки чередуются в каждом раунде шаров; дополнительный шар
остаётся у заработавшего его игрока. Подробности: [PF12.1](analysis/pf12.1-hotseat.md).

## Настройки

Нативный экран настроек F5 содержит:

- **BALLS:** 3 / 5
- **ANGLE:** HIGH / LOW
- **SCROLLING:** HARD / MEDIUM / SOFT / **OFF**
- **MUSIC:** ON / OFF
- **RESOLUTION:** NORMAL / HIGH
- **SAVE AND EXIT**

`NORMAL` и `HIGH` сохраняют восстановленные DOS-варианты viewport. При `SCROLLING: OFF` визуально используется полный кадр 320×609, но выбранное разрешение сохраняется и снова применяется после возврата к прокрутке.

Исторический DOS-режим monochrome сохранён только для археологии/тестов и не показывается как обычная нативная настройка.

## Полноэкранный режим и окно

В селекторе, настройках, attract mode и самой игре используется одно постоянное нативное окно.

`Alt+Enter` переключает **borderless desktop fullscreen**. Режим монитора и частота обновления при этом не меняются. После выхода из fullscreen восстанавливаются прежние положение и состояние окна.

В Windows и Linux потеря фокуса ставит активную игру на паузу. Возврат фокуса
оставляет паузу включённой; для продолжения нажмите игровую клавишу, например `P`.

Windows проверяет фактическое held-state на каждом Pump/tick, отдельно для
левых и правых Shift/Ctrl/Alt. Для retest задайте `PF12_INPUT_LOG=1` перед
запуском: `input.log` появится рядом с `native.log`. Подробнее — в
[отчёте по held-input](analysis/pf12-held-input-fix.md).

Логическое соотношение сторон сохраняется с letterbox/pillarbox при необходимости; искусственная коррекция в 4:3 к изображению стола не применяется.

## Точность относительно исходника и детерминизм

Цель проекта — максимально сохранить оригинальную игру, при этом запуская её нативно на современных системах.

Реализация постоянно проверяется по поведению, восстановленному из исходников и данных. Например:

- checker достижимости matrix-команд: ноль отсутствующих runtime targets на всех четырёх столах;
- аудит operands/source text: ноль неразрешённых операндов и ноль несовпадений байтов текста в проверенном наборе;
- детерминированный oracle Party Land: **1200 ticks → 2 300 000 очков, ball 2**;
- режим полного стола сравнивается с эквивалентными игровыми сессиями через обычный scrolling renderer;
- проверяется, что частота host presentation не меняет детерминированный PCM и итоговое логическое состояние игры;
- исходные файлы игры хешируются до и после валидации, чтобы убедиться, что нативный порт их не переписывает.

Отчёты в [`analysis/`](analysis/) описывают реконструкцию по этапам и отдельно фиксируют известные ограничения и неопределённости.

## Архитектура

В общих чертах:

```text
оригинальные DOS-данные
          │
          ▼
 декодеры ассетов / столов
          │
          ├── физика + правила столов
          ├── renderer команд матрицы
          ├── tracker / sample mixer
          └── frontend + настройки
                    │
                    ▼
             platform boundary
             ├── Linux / SDL2
             └── Windows / Win32 + GDI + waveOut
```

Игровая реализация общая. Windows — не отдельный переписанный вариант, и ни одна платформа не исполняет оригинальный x86-код во время работы.

## Сборка из исходников

Подготовка и сборка Linux:

```sh
python3 tools/setup-local.py
./tools/go.sh build -buildvcs=false -p=1 -o bin/pinballfantasies ./cmd/pinballfantasies
./bin/pinballfantasies -data-dir "/path/to/Pinball Fantasies"
```

Кросс-сборка Windows:

```sh
./tools/build_windows.sh
```

Публичные release-артефакты без игровых данных:

```sh
./tools/build_release.sh
```

Локальные персональные self-contained Windows + Linux сборки (с коммерческими
данными; не предназначены для распространения как релизы проекта):

```sh
./tools/build_personal_release.sh "/path/to/original/Pinball Fantasies"
```

Полный набор Go-тестов:

```sh
./tools/go.sh test -p=1 -count=1 ./...
```

Проверки матрицы по исходникам:

```sh
python3 tools/matrix_reachability.py --check
python3 tools/matrix_operand_audit.py --check
```

Более подробные инструкции находятся в [docs/build.md](docs/build.md). Детали реализации Windows описаны в [отчёте PF12](analysis/pf12-windows-native-port.md), а упаковка — в [отчёте о portable release](analysis/pf12-portable-release.md).

## Чем этот порт необычен

Pinball Fantasies — небольшая по современным меркам игра, но для нативного воспроизведения пришлось заново собрать удивительно много тесно связанных механизмов DOS-эпохи, а не просто перерисовать четыре стола.

В порте уже работают все четыре оригинальных стола, восстановленные правила каждого из них, matrix-программы по исходникам, целочисленная физика, нативное воспроизведение модулей и samples, постоянное состояние frontend, платформенные backend'ы, borderless fullscreen и новый режим показа всего стола — при этом детерминированные проверки продолжают сверять поведение с исторической реализацией.

После реконструкции DOS-аудиотракта исходный четырёхканальный материал также получил стереоразделение, соответствующее раскладке каналов Amiga Paula.

## Известные ограничения beta

На некоторых Linux-системах с несколькими мониторами вход/выход из fullscreen
может ненадолго вызвать мерцание или перемещение окна между экранами.

Есть нативная Windows-сборка Win32/GDI/waveOut. Hosted native Windows build/tests
и описанные Wine/live development проверки проходят. Это не означает исчерпывающую
проверку всех сочетаний multiplayer/fullscreen/audio на физических Windows-машинах.
Wine не эквивалентен проверке на настоящем Windows-оборудовании.
Нативный шрифт боковой панели 5x7 визуально отличается от PC BIOS.

Проверка без оригинальных файлов:

```sh
./tools/go.sh test -p=1 -count=1 ./...
python3 tools/check_public_source.py
python3 -m unittest discover -s tools -p 'test_*.py'
```

Тесты с оригиналами/приватными captures/историческими исходниками явно
пропускаются, если этих внешних входов нет. Public CI не скачивает такие входы.
`matrix_reachability.py --check` и `matrix_operand_audit.py --check` — отдельная
проверка реконструкции с внешними историческими ASM и оригинальными TABLE PRG.

Исторические отчёты в analysis/ описывают состояние на момент их создания;
их прежние публикационные ограничения заменены решением владельца о выпуске
этой публичной MIT beta. Party oracle сохранён: 1200 ticks, `000002300000`, ball 2,
frame SHA256 `f9b5160b3173c35f2798dd5e270e7ded40c33642605e21c0935cd083ff231a5e`.
